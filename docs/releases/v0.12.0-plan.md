## Release thesis

### Product-owner scope amendment — 2026-08-20

The original plan intentionally used an all-or-nothing production-certification bar.
That bar is now narrowed to match the project's current maturity. Version 0.12 must be
feature-complete and polished on its supported paths, with a world-class public
interface, developer experience, documentation, diagnostics, migration story, and
support surface. It must also meet a reasonable safety baseline: no known
release-severity ownership, credential, policy-bypass, ambiguous-effect, data-loss, or
artifact-integrity defect.

Production-scale hardening is no longer a blanket release prerequisite. Multi-AZ
quorum, STONITH/watchdogs, hostile network/certificate matrices, production-volume
RPO/RTO, long multi-worker soak, exhaustive provider/vector-store breadth, long-duration
learning drift, advanced telemetry chaos, and recovery of arbitrary unsupported
nested/parallel/raw/streaming/parser/output-model graphs may graduate in later releases.
Version 0.12 must state those boundaries precisely and fail closed before effects where
an explicit profile would otherwise promise an unsupported guarantee.

This amendment supersedes earlier statements that every production-certification item
must close before 0.12 can ship. It does not waive common-path feature correctness,
security basics, tests, packaging, documentation, or truthful compatibility claims.

`0.12.0` makes `agnoclaw` a complete, trustworthy embeddable agent runtime without
losing its small `AgentHarness.run()` and `AgentHarness.arun()` surface. The release
must serve cheap short runs and recoverable long-running work through one isolated run
kernel; persist trajectory, effects, artifacts, and context; make every Agno learning
mode scoped and measurable; discover capabilities lazily; govern dangerous actions;
and give every client the same lifecycle protocol.

The release name is **World-Class Harness Runtime**. Alpha milestones and release
candidates are rollback boundaries, not scope cuts. Final `0.12.0` does not ship until
all core workstreams in this document meet their gates. A preceding `0.11.x` truth and
safety patch may reduce present risk, but it does not replace any `0.12.0` requirement.

The version remains `0.12.0`, not `1.0.0`. This is a large capability release, while a
`1.0.0` stability promise still requires production soak, adoption evidence, and at
least two released minors of compatibility history for the new lifecycle APIs.

## User outcome

After upgrading, an application developer can:

```python
harness = AgentHarness(
    model="anthropic:claude-sonnet-4-6",
    profile="durable",
    learning=LearningProfile.personal_and_session(...),
)

run = await harness.start("Investigate the incident", session_id="incident-42")
async for event in run.events():
    ...
result = await run.wait()
```

They can also keep using:

```python
result = await harness.arun("Investigate the incident")
```

with no required migration. The convenience call routes through the same isolated run
kernel as `start()`.

## Premises to confirm

1. **World-class is the acceptance bar.** Cross-run isolation, durable continuity,
   truthful learning, context control, capability discovery, safety, evaluation, and
   documentation are all required core scope. Sequencing controls risk; it does not
   defer any of them past final `0.12.0`.
2. **One kernel, two time scales.** Short and long-running agents should share one run
   model. Short runs keep in-memory defaults; durable stores are adapters, not a second
   harness.
3. **Agno-native, not Agno-pass-through.** Reuse Agno's Agent, LearningMachine,
   cancellation, continuation, environment, scorer, and FileSystem capabilities, but
   expose only behavior `agnoclaw` can validate across supported versions.
4. **No silent compatibility.** `agno>=2.6.4` without an upper bound is unsafe while
   only 2.6.4 is locked and tested. Development starts with a 2.6.4 legacy lane, Agno
   2.9.0 as the primary 2.x lane, and the newest Agno 3 prerelease as a non-production
   preview lane. Prereleases are never admitted through the stable dependency range.
   At RC freeze, the newest stable Agno release must pass the full contract suite; the
   exact final range is generated from a signed compatibility manifest rather than
   guessed from semver.
5. **No self-improvement theater.** Learned Knowledge requires vector-backed Agno
   `Knowledge`; Session Context is explicit; every learning write is scoped. Invalid
   configurations fail before a model call.
6. **Migration should be boring.** Existing `run/arun`, tools, workspace, policy,
   permission, hooks, events, CLI, TUI, and AgentOS entry points continue to work. New
   contracts are additive; old learning booleans enter a documented deprecation window.
7. **Stable means proven.** Existing `run/arun` behavior can be stable after its gates;
   newly introduced lifecycle surfaces are labeled preview in `0.12.0` and may graduate
   only after concurrency, recovery, cancellation, event, and compatibility evidence
   across two released minors. Preview describes evolution risk, not incompleteness.
8. **Small means fewer public decisions, not fewer guarantees.** The stable public
   grammar is `AgentHarness`, `HarnessSession`, and `HarnessRun`; runtime choice is
   `quick`, `durable`, or `service`; one `RuntimeStore`, one `ArtifactStore`, and one
   `CapabilitySpec` sit at extension boundaries. Internal reducers, gateways,
   projections, and materializers earn their existence through a named invariant and
   are not peer concepts an ordinary user must assemble.
9. **Improvement is a falsifiable change, not reflection.** Every proposed harness or
   durable behavioral change names verifier-grounded evidence, causal weakness,
   bounded editable components, predicted benefit, regressions at risk, held-in and
   held-out results, and rollback. The evaluator, model/config, budgets, raw runs, and
   permission boundary remain immutable to the proposer.

## Scope

### R1. Supported-runtime contract

- Start development with a bounded Agno 2.x range, keep the `0.11.x` patch compatible
  with the existing 2.6.4 lock, and certify 2.9.0 as the primary 2.x lane. The current
  range is `agno>=2.6.4,<2.10`. Run the newest
  Agno 3 prerelease in a separate preview lane that cannot satisfy or enter the stable
  dependency range.
- At RC freeze, certify the newest stable Agno release. If Agno 3 stable has existed
  for at least 60 days and passes the full contract plus migration/rollback suite, make
  it primary and retain a 2.x compatibility lane only when evidence justifies it. If a
  stable Agno 3 exists but fails a critical contract, delay 0.12 instead of claiming
  latest support. If 3 remains prerelease, cap production below 3 and publish the
  preview report.
- Test the release minimum, primary stable, and newest prerelease in CI. A preview-lane
  failure needs a triaged owner and expiry; it is not silently ignored. Upgrade the
  development lock only after the compatibility suite passes.
- Expand the Python contract from the current project-only `>=3.13` assumption to a
  certified matrix targeting 3.11-3.14. A lane ships only when Agno, MCP, every required
  database/serialization dependency, package installation, and the full contract suite
  pass; unsupported interpreters fail installation clearly.
- Minimize the core wheel and import graph. Move provider clients, web/search,
  scheduler, database, TUI, MCP, and other non-kernel dependencies behind
  outcome-named extras when the deterministic SDK path does not require them. Gate
  clean-install size, import time, dependency count, and `pip check` for core plus every
  documented extra; one recommended install remains obvious.
- Add `agnoclaw.compat` with explicit capability probes and actionable configuration
  errors. Do not spread `hasattr` compatibility checks through product code.
- Maintain a release-delta inventory with an adopt/adapt/avoid decision and a contract
  test for every harness-relevant upstream change. Add deprecation/static scans for
  model-routing defaults, human-review arguments, learning/history parameters,
  component serialization, session/run storage, and protocol surfaces.
- Publish `docs/compatibility.md` with Python, Agno, provider, storage, AgentOS, MCP,
  and optional-extra support levels.
- Use Agno 2.8 scorers and isolated rollout environments in evaluation adapters where
  available; retain a 2.6-compatible fallback for the minimum lane.
- Before freezing the runtime schema, write an ADR deciding whether stable Agno 3
  normalized run rows, its job queue, and its event streams conform as projections or
  adapters. Do not duplicate those upstream systems, but do not substitute them for the
  canonical RuntimeStore/OperationGateway unless atomicity, tenancy, recovery, effect,
  cursor, migration, and load gates all pass.

### R2. Isolated run kernel

- Evolve existing `HarnessConfig` as the single public validated configuration model.
  The run factory may compile it into a private immutable `_HarnessSpec`; that type is
  not public configuration. Profiles are named constructors/default bundles over
  `HarnessConfig`.
- Materialize a fresh run-scoped Agno Agent/runtime view for every execution through
  explicit `CapabilityMaterializer` contracts; never assume arbitrary caller-supplied
  Model, Toolkit, Function, retriever, or storage objects are safely deep-copyable.
  Built-ins, packs, and MCP descriptors create per-run instances; an explicitly
  declared immutable/thread-safe object may be shared; unclassified legacy objects are
  serialized in compatibility mode and rejected by safe-default `durable` and
  `service` execution.
- Every materializer declares `run`, `session`, or `process_pool` lifetime; concurrency
  and reentrancy; async acquire/close; logical snapshot/checkpoint support; crash and
  reconciliation behavior; and whether a live resource can recover. Session state is
  stored, not hidden in a Toolkit object. Browser pages, subprocesses, MCP sessions,
  and other live handles are leased and either restored through a certified backend or
  reported explicitly non-recoverable.
- Route `run()` and `arun()` through the same internal run factory.
- Keep `underlying_agent` only as a deprecated, explicitly unsafe compatibility escape
  hatch in `0.12.x`; accessing it voids isolation/lifecycle guarantees for that caller,
  is never used by first-party adapters, and is unavailable in `durable`/`service`
  profiles. Removal follows the normal deprecation window.
- Preserve model-hidden dependency and tool-argument binding without mutating shared
  Function or Agent definitions.
- Compile deep-copied scalar/container configuration into `_HarnessSpec` and retain
  factories or immutable descriptors for live resources. Mutable caller configuration
  and caller-owned object graphs never remain authoritative after construction.
  `ExecutionContext.metadata` is deep-copied/frozen at admission; the process-cached
  mutable `HarnessConfig` never leaks into a compiled runtime.
- Materialize workspace, sandbox, temporary-file, artifact, and cache namespaces from
  the resolved tenant/session/run identity. A harness-wide directory is not advertised
  as session isolation; every list/read/snapshot/reset operation reauthorizes the exact
  namespace it touches.
- Serialize turns within one `session_id`; allow bounded concurrency across different
  sessions.
- Add adversarial overlap tests for prompts, tools, skill choice, output schema,
  dependencies, session state, permissions, user/tenant identity, and cancellation.
- Ship only three orthogonal runtime profiles: `quick` (ephemeral), `durable` (SQLite
  reference), and `service` (certified PostgreSQL multi-worker). A `session_id` selects
  continuity and serialization; it is not a profile. Safe capability, sandbox, network,
  and approval policy is the explicit-profile default. `HarnessConfig.local_safe()` is
  a convenient policy/backend preset that composes with `quick` or `durable`, not a
  fourth runtime semantic. `HarnessConfig.legacy()` is an isolated compatibility
  constructor, never a normal profile or first-party execution path.

### R3. Durable lifecycle and one run facade

- Evolve the existing `HarnessRun`; do not create a competing `AsyncRunHandle` or a
  second public configuration hierarchy.
- Add `AgentHarness.start(..., idempotency_key=None)` returning `HarnessRun`. Preserve
  the existing completed `.result` value. Freeze only `wait()`, `status()`, `events()`,
  `cancel()`, and one typed `command()` control channel on `HarnessRun`; `command()`
  accepts versioned pause, resume/input-or-approval response, steering, and fork
  commands. This implements the complete lifecycle without growing one ad-hoc method per
  command before semantics are proven. `events(after=cursor)` plus the authorized run
  snapshot provide read-only reconstruction; a fork command alone starts a new
  effect-capable run from a certified checkpoint. Deterministic re-execution is
  evaluation-only with effects disabled.
- A run is exactly one logical requested execution and terminal states are immutable.
  `HarnessSession.start()` creates the next run/turn; a “follow-up” never extends a
  terminal run. Steering is accepted only before the declared safe point and has an
  explicit applied/rejected event. Pause/resume and fork are preview command variants in
  `0.12.0`; their behavior is fully implemented and tested, while the single command
  envelope can evolve without multiplying top-level methods.
- Add authorized `AgentHarness.get_run(run_id, *, context=...)` reattachment and matching
  versioned AgentOS/remote GET, result, cursor-event, and lifecycle-command endpoints.
  A nonterminal handle has `.result is None`; a completed handle populates it after
  `wait()`, terminal event observation, or reattachment. Failed/cancelled/expired waits
  raise a typed redacted error carrying the authorized terminal snapshot, and leave
  `.result` as `None`.
- Scope start idempotency to tenant plus admission principal. Reusing a key with the
  same canonical request digest returns the original `run_id`; reusing it with different
  input, identity, profile, capability/policy snapshot, or material configuration raises
  `IdempotencyConflictError`. Profiles document key retention and expiry.
- `events(after=None, follow=None)` yields a gap-free snapshot and, when the run is still
  active, follows through the first immutable run-terminal event, then ends. Explicit
  `follow=False` is snapshot-only; `follow=True` may continue after terminal for late
  effect reconciliation/retention events until caller cancellation or timeout and emits
  typed heartbeats without consuming sequence numbers. `wait()` is independent, so a
  slow or disconnected event consumer never blocks execution.
- Define versioned states: `created`, `queued`, `running`, `waiting_for_input`,
  `waiting_for_approval`, `waiting_for_reconciliation`, `paused`, `cancelling`,
  `completed`, `failed`, `failed_with_unknown_effects`, `cancelled`, and `expired`.
  Every transition has one owner and an idempotency rule.
- Persist run metadata, transitions, typed events, checkpoints, result references, and
  errors before acknowledging them. Use monotonically increasing per-run sequence
  numbers and opaque cursors for reconnectable at-least-once consumption with client
  deduplication.
- Recover nonterminal runs after process restart. Resume from a certified checkpoint,
  or fail with an explicit recovery classification; never silently restart a model turn
  or tool effect.
- Before schema or public lifecycle freeze, run a stop/go spike on both certified Agno
  minors with process death after provider dispatch, after response receipt, before
  capability dispatch, during approval/input wait, during a capability, and after its
  return. Checkpoints exist only at proven operation boundaries. If Agno cannot expose a
  serializable boundary, agnoclaw owns the thin provider/tool orchestration loop while
  continuing to reuse Agno models, messages, learning, sessions, and adapters; the
  release does not downgrade “durable continuation” into mere crash recording.
- Preserve Agno continuation and cancellation where certified, but make agnoclaw's
  durable state machine the client contract.
- Specify ownership at the Python task/process edge: cancellation of the caller task
  does not silently cancel a detached durable run; `close()/aclose()` stop new
  admissions and either drain, detach, or cancel by explicit policy; disconnects never
  change run state; graceful worker drain releases or transfers leases; double cancel
  is idempotent and returns the authoritative state.
- Preserve `run/arun(stream=True)` in `0.12.x` through a named compatibility adapter
  that yields the existing raw Agno stream while the same coordinator records normalized
  `HarnessEvent` envelopes. New code, CLI, TUI, AgentOS, and remote clients consume the
  typed event protocol. Deprecation starts only after equivalent migration helpers and
  cannot remove the raw adapter before `0.14.0`.
- Freeze the public grammar in one API table: blocking convenience `run()`, async
  convenience `arun()`, controllable `await start()`, reattachment `get_run()`, and
  async lifecycle methods on `HarnessRun`. Add `HarnessSession.start()` for live control
  while preserving `HarnessSession.send()` as the completed compatibility operation;
  docs never imply they have identical completion timing.
- Keep existing `agnoclaw run` as the one-shot command. Lifecycle inspection and
  commands live under `agnoclaw inspect run <run_id>` rather than turning `run` into an
  ambiguous command group. Every non-interactive command supports stable `--json`,
  `--no-color`, documented exit codes, and terminal-vs-pipe output detection.

Normative final runtime-profile contract:

| Profile | Persistence/restart | Identity and concurrency | Learning/retention | Intended cost |
|---|---|---|---|---|
| `quick` | Ephemeral runtime; no restart or cursor-after-process guarantee | Optional identity; isolated concurrent runs; `session_id` may serialize work but is not durable by default | Off by default; run-lifetime context | Minimum |
| `durable` | Certified SQLite `RuntimeStore`, artifacts, checkpoints, cursors, and single-node restart recovery | Trusted identity; serialized session lanes; worker lease/fencing contract | Permitted scoped intents; explicit retention/deletion | Storage-bound |
| `service` | Certified PostgreSQL `RuntimeStore`, artifacts, multi-worker recovery, backup/restore, and published RPO/RTO | Tenant/user/session required; bounded fair admission and fenced workers | Explicit scope/consent/tenant retention | Deployment-bound |

Every explicit profile is least-privilege by default. Local filesystem/sandbox/network
posture is selected through `HarnessConfig.local_safe()` or equivalent policy fields,
not encoded as persistence semantics. Legacy behavior exists only behind
`HarnessConfig.legacy()` and the alpha/RC legacy-runner adapter. Common identity, state,
terminal, policy, event, error, and operation semantics never vary. A requested profile
fails construction when its store, artifact, capability, or execution class cannot
enforce the claim.

### R4. Correct learning and memory

- Make `LearningProfile` a convenience constructor for immutable `LearningPolicy`; it
  is not a third peer configuration system. Resolve structured `LearningScope` from
  trusted identity at run admission.
- Expose User Profile, User Memory, Session Context, Entity Memory, Learned Knowledge,
  and Decision Log by intent, not only by booleans.
- Require `tenant_id`, `user_id`, `session_id`, and namespace fields where the selected
  profile needs them.
- Require vector-backed Agno `Knowledge` before enabling Learned Knowledge.
- Surface Agno's extraction tool-call limit where supported to prevent unbounded
  learning loops.
- Replace the nonexistent `optimize_memories()` path with a version-certified curator
  operation or remove the maintenance promise. No silent no-op is acceptable.
- Introduce `LearningGateway`: `quick`/legacy may use explicitly documented direct Agno
  behavior, but acknowledged `durable`/`service` writes either use a scope-enforcing
  ledger-compatible Agno adapter or become stable-source-ID extraction commands and
  candidates projected through the outbox. Raw `LearningMachine` mutation cannot sit
  outside the run transaction while the API claims durable learning.
- Add behavioral tests proving save, scoped recall, cross-scope denial, delete, conflict,
  and failure behavior. Constructor-shape tests do not count.
- Reconcile ambiguous learning effects with an exact-state observer under a dedicated
  owner-scoped database-clock lease, monotonic takeover fence, heartbeat, and durable
  cursor. Maintenance may repeat read-only inspection after a crash but never the
  promotion/rollback effect; custom backends must supply a matching observer.
- Keep existing learning booleans working through a compatibility adapter in 0.12.x,
  emit one deprecation warning per harness, and remove them no earlier than 0.14.0.
  Map each boolean explicitly. Previously nonfunctional Learned Knowledge combinations
  fail with a migration message; compatibility never recreates the silent failure.

### R7. Trajectory, effects, artifacts, and recovery

Implementation checkpoint (2026-08-12): the PostgreSQL service lane has bounded-pool
overload, process-local tenant fairness, exact-owner/noisy-neighbor latency gates, and
an automated loopback native dump/restore rehearsal. It also applies the finite connect
timeout to each libpq connection, converts acquired-connection loss into a non-retryable
re-read/reconciliation boundary, and repeatedly passes an exact-container
single-primary stop/start drill with bounded failure, pool recovery, fence/state/event
continuity, healing, cleanup, and a two-connection cap. The restore rehearsal matches every
runtime row plus columns, indexes, constraints, sequences, ordered events, and start
idempotency, then removes its exact dump/target/marker independently. This closes the
isolated store-restore and single-primary-outage regression slices. An owned two-node
gate also proves positive lag, acknowledged-LSN catch-up, old-primary fencing, planned
promotion, a bounded no-writer interval, and read-write pool reattachment across five
runs. A synchronous companion has five completed hardened passes proving exact required-
standby false-ack prevention, replay-before-acknowledgement, abrupt-primary-loss
recovery with zero observed acknowledged state/event/fence loss, and bounded existing/
fresh-pool reattachment. A round-trip companion has five hardened passes: it uses
exact checkpoint/replay boundaries, rewinds/rejoins both stopped former writers without
persisting recovery passwords, returns the writer role to the original node, and
preserves exact state/events/fences through existing and fresh pools. Deployment-
specific application writer authority now has a fail-closed contract and first-party
etcd v3 adapter: pinned cluster identity, bracketed linearizable reads, lease
attachment/TTL, `mod_revision` fencing, real two-writable-timeline stale/outage/server-
timeout/commit-rollback proof, and standalone revoke/expiry/loss proof pass. An owned
three-voter gate also closes the local TLS 1.2 client/peer mTLS, exact-key RBAC,
endpoint-token, one-member-loss, majority-loss, alternate-endpoint recovery, and fence-
advance regression. This does not close external controller election/record ownership,
durable multi-AZ production quorum/backup, arbitrary-client/paused-host
watchdog/STONITH, network partition/latency/certificate rotation,
simultaneous/
multiple-failure, production synchronous-latency/availability and RPO-policy,
endpoint-discovery/rejoin automation, large-data/archive rewind, encrypted off-host
retention, artifact/key recovery, PITR, corruption response, and production RTO remain
required by R7/T5b.

- Expose one transactional `RuntimeStore` extension boundary owning runs, events,
  operations/effects, checkpoints, leases, idempotency, jobs, learning commands, and
  its outbox. Trajectory/effect/checkpoint/job views are internal repositories or
  rebuildable projections, never independently swappable stores that could break atomic
  commit. Expose one separate `ArtifactStore` because external bytes are staged by
  content hash before an atomic ledger reference and unreferenced bytes require grace-
  period garbage collection.
- Ship and certify two real implementations: SQLite/WAL for the single-node `durable`
  reference and PostgreSQL for `service`. PostgreSQL must define transaction isolation,
  database-clock leases, fencing, tenant-aware indexes/partitioning, cursor retention,
  migrations, connection-pool bounds, backup/restore, corruption response, and tested
  RPO/RTO. Notifications are hints only; an ordered `RuntimeStore` cursor read remains
  authoritative under dropped notifications or replica lag.
- Make the runtime ledger and its state reducer the source of truth. The existing
  callback `EventSink` becomes an export observer driven from the committed outbox; a
  successful or failed callback can never determine whether a lifecycle transition or
  effect committed. Agno session, history, and learning writes are projections or
  separately settled effects, because their stores cannot be assumed atomic with the
  agnoclaw ledger.
- Preserve legacy `EventSinkMode.FAIL_CLOSED` only on the legacy runner. In the new
  kernel, a required-export failure can stop future dispatch or move the coordinator to
  an explicit waiting/failure state according to `OutboxDeliveryPolicy`, but it never
  rolls back or contradicts an already committed transition. Deprecate the old option
  with a precise migration table.
- Record provider/model requests, tool calls, approvals, context mutations, learning
  candidates, child runs, scheduler attempts, artifacts, and terminal outcomes as a
  typed trajectory.
- Give every nondeterministic or externally visible operation a correlation key,
  lifecycle state, retry policy, request digest, attempt, cost/usage, provider request
  ID when available, and one canonical local settlement. Record provider-enforced
  idempotency only when it really exists. Model calls have an explicit crash policy;
  they are never assumed replay-safe merely because they are not conventional tools.
  Capability effects are classified as read-only, idempotent, compensatable, or
  non-repeatable.
- Route every dispatch path through one internal `OperationGateway` before execution:
  provider/model calls, built-in and caller tools, context-provider tools, MCP, skill
  commands, elevated/background commands, child runs, and scheduled work. One public
  `CapabilitySpec` declares factory, lifetime, trust, scopes, effect class, idempotency,
  and recovery behavior. Raw `tools=` input is normalized to a spec; opaque legacy
  functions are serialized only in compatibility mode and rejected by `durable` and
  `service`. No adapter may bypass policy, intent persistence, budgets, or settlement by
  reaching Agno directly.
- State cancellation honestly: cancellation stops new work and waits for, abandons, or
  compensates in-flight effects according to policy. Unknown non-repeatable outcomes
  enter `waiting_for_reconciliation`; an authorized operator may settle them, or policy
  may end the run as `failed_with_unknown_effects` after escalation/retention deadlines.
  It never claims to undo an effect that already committed.
- Encrypt or redact sensitive payloads before persistence, enforce retention/deletion,
  and make reconstruction/fork authorization equivalent to original-run authorization.
- Add startup recovery, lease stealing after expiry, duplicate-delivery defense, store
  migration/versioning, backup/restore, and chaos tests.
- Provision the canonical result/artifact identity in the operation intent before any
  external dispatch. Settlement must reject an unprovisioned or mismatched fulfillment
  rather than attaching plausible bytes to the wrong operation.
- Ship deterministic effect stepping in `agnoclaw.testing`: pause after every durable
  operation state, close and reopen the store, inject the effect result, then exercise
  both race orders for cancel/complete, lease-loss/commit, timeout/result, and
  reconcile/terminal cleanup. The write oracle is shared by SQLite and PostgreSQL.
- Keep recovery work bounded and index-driven. Certification must prove query plans and
  history-size-independent lookup behavior for run, checkpoint, operation, child, and
  reconciliation discovery at representative retained-history sizes.
- Define overload as public behavior: bounded global/tenant/session admission queues;
  weighted tenant fairness; maximum in-flight runs, writer queue, batch, event page,
  delta segment, stream buffer, artifact, and subscriber lag; typed `OverloadedError`
  with retry hints; observer disconnect/cursor recovery instead of coordinator stalls;
  and no unbounded in-memory trajectory. Publish noisy-neighbor, slow-consumer,
  partition, saturation, and recovery benchmarks with p50/p95/p99 and memory ceilings.

### R8. Learning and measured self-improvement

- Separate immutable `LearningPolicy` (allowed learning intents, extraction limits,
  evaluation and promotion policy) from run-resolved `LearningScope` (tenant, user,
  session, entity, namespace, retention, consent).
- Correctly wire Agno User Profile, User Memory, Session Context, Entity Memory,
  Learned Knowledge, and Decision Log. Learned Knowledge requires vector-backed
  `Knowledge`; unavailable capabilities fail before a model call.
- Persist candidates with source trajectory, evidence, scope, extraction version,
  confidence, and expiry. Never promote raw model reflection directly into trusted
  memory, policy, prompt, or skill state.
- Represent every editable harness surface in a versioned internal
  `HarnessComponentManifest` using seven observable classes: system prompt, tool
  description, tool implementation, middleware, skill, subagent configuration, and
  long-term memory. This is an operator/evaluation contract, not seven public runtime
  objects. Policy, identity, evaluator, model configuration, budgets, and raw evidence
  remain outside the editable surface.
- Separate generator, reflector/diagnoser, curator, and evaluator responsibilities.
  Each output records its role, mechanism version, input evidence, and artifact
  lineage; neither reflection nor chain-of-thought is outcome evidence by itself.
- Mine failures into verifier-grounded causal clusters. A terminal label such as
  timeout or missing artifact is not a root cause. Bounded proposals receive relevant
  failures, passing behaviors to preserve, previous attempts, explicit edit surfaces,
  and no unrelated workspace authority.
- Require an immutable `ChangeHypothesis` for every proposed harness/behavior edit:
  evidence, inferred root cause, targeted components/files, predicted fixes,
  at-risk regressions, model/config/evaluator digests, budget, and rollback target.
- Session Context and explicitly user-authored profile facts may write directly to their
  exact session/user scope. Inferred personal memories may use Agno direct writes only
  when policy permits, remain inspectable/editable, and never mutate policy/prompt/skill
  code. Entity Memory, Learned Knowledge, Decision Log, and any cross-user,
  institutional, behavioral, prompt, policy, or skill change always use the candidate
  evaluation/promotion pipeline.
- Evaluate candidates against held-out and shadow rollouts with Agno scorers where
  supported. Promotion requires statistically meaningful benefit, no safety regression,
  and explicit policy; every promotion is versioned and reversible.
- Evaluate targeted held-in cases, untouched held-out cases, and frozen-candidate
  transfer to a disjoint task class. Preserve rejected and negative candidates, enforce
  novelty/diversity checks, and retain qualified candidates on a Pareto frontier across
  quality, safety, cost, latency, and complexity rather than optimizing one scalar.
- Keep benchmark cases, verifiers, raw run records, accepted budgets, model/config, and
  permission controls read-only to the proposer. Separate proposer and evaluator
  contexts/authority; balance LLM-judge candidate ordering, record disagreements, and
  prefer objective external feedback. Ambiguous or heuristic-only evaluation permits
  candidate collection, not autonomous promotion or an improvement claim.
- Stable `0.12.0` behavior captures candidates and supports host/operator-approved
  promotion, inspect/edit/delete/forget, provenance, consent, and rollback. Automatic
  promotion, decay, and any prompt/policy/skill mutation ship only as explicit
  experimental evaluator policies, disabled by default and unable to bypass the same
  authorization/evidence gates. “Self-improvement” never means autonomous code or
  policy mutation in the stable profile.
- Support inspect/export/edit/delete/forget, conflict resolution, decay, rollback,
  poisoning quarantine, and legacy namespace migration.
- Report learning benefit against a no-learning control by task class, not merely write
  counts. No automatic self-improvement claim ships without this evidence.

- Replace implicit bypass behavior deterministically: legacy constructor shapes retain

  `HarnessConfig.legacy()` migration target; every explicit profile uses its documented

  examples. A later release may flip the unprofiled legacy path only through normal
  deprecation.
- Apply policy at run, prompt, capability discovery, tool invocation, effect commit,
  artifact access, learning read/write/promotion, child-run spawn, and
  reconstruction/fork boundaries.
- Bind tenant/user/session identity from trusted host context, never model-authored
  arguments. Propagate it through stores, events, logs, caches, and child runs.
- Define one claims-first merge algorithm for SDK, AgentOS, remote, CLI, scheduler, and
  child-run admission. A less-trusted body/path value may fill an absent optional field
  but never override a trusted claim; a conflict is a typed authorization error and is
  audited without leaking either value.
- Resolve one immutable `AdmissionEnvelope` before policy, storage, prompt construction,
  Agno invocation, or telemetry. Explicit kwargs, `ExecutionContext`, authenticated
  claims, host grants, and path/body fields have a documented precedence/trust matrix;

  client metadata is data, never authority.
- Add approval requests as durable waiting states with expiry, approver identity,

- Treat preapproval metadata and cached grants as trusted authorization inputs, never

- Add secret isolation, output redaction, sandbox/network/filesystem constraints,
  resource quotas, supply-chain checks for skills/MCP, audit export, deletion, and
  adversarial prompt/tool-result injection tests.
- Redact and classify at typed-error construction before persistence, propagation,
  events, or telemetry; sanitizing only at an exporter cannot undo a ledger leak.

## Product boundaries, not deferred harness work

No core harness subsystem is deferred past final `0.12.0`. The following are separate
products or ecosystem surfaces and are not required to call the embeddable harness
world-class:

- a hosted multi-tenant control plane or managed execution service;
- end-user channel gateways for Slack, WhatsApp, email, or voice;
- a commercial capability marketplace and billing system;
- a new graphical operations console;
- independent distributed compute orchestration beyond the documented durable-store,
  lease, and worker contracts;
- a `1.0.0` stability declaration.

The kernel must expose clean adapters for these consumers, and existing CLI, TUI,
AgentOS, and remote surfaces remain supported. None may create a second execution path.

## Architecture delta

```text
0.11.0
caller -> AgentHarness (configuration + mutable run state) -> shared Agno Agent

0.12.0
caller/client -> AgentHarness facade -> AdmissionEnvelope -> RunCoordinator
                                                           |        |
                                             RuntimeTransaction    per-run materializer
                                                           |        |
                                              ledger + outbox      Agno Agent
                                               /   |   \             |
                                      effects/artifacts/jobs   CapabilityPlane
                                               |                  |
                                   approvals + recovery     Context/LearningGateway
                                               \                  /
                                           telemetry + evaluation evidence
```

`run()` and `arun()` become convenience adapters over `start()` plus `wait()`. Quick
runs may use an ephemeral store profile, but they obey the identical isolation, state,
policy, and event contracts. No CLI, TUI, AgentOS, remote, scheduler, or subagent path
may bypass the run factory.

## Change-management policy

### Compatibility

- Public removals require a deprecation warning in at least two minor releases.
- Preview APIs may change, but every change is documented with a before/after example.
- The minimum and latest certified Agno versions are CI gates, not documentation-only
  promises.
- Lockfile upgrades and public dependency-range changes are separate reviewable commits.
- Machine-readable deprecation metadata powers warnings, docs, and migration tooling.
  Each warning has a removal floor, old/new code, behavior change, and one exact command
  or edit; warnings are testable and never emitted once per process without identifying
  which harness/config triggered them.

### Rollout

- New kernel behavior is exercised internally by `run/arun` from the first alpha. A
  temporary `AGNOCLAW_LEGACY_RUNNER=1` escape hatch is allowed only in alpha/RC builds,
  rejects concurrency and every new durability feature, emits a distinct event marker,
  and is absent from final `0.12.0`. Final rollback uses the previous package plus the
  documented compatible schema boundary.
- Learning migration is opt-in for new explicit profiles; legacy booleans route through

## CEO review: SCOPE EXPANSION

Primary customer: a Python developer embedding one shared agent harness into a product
or internal service. The first magical moment is a networked sub-two-minute no-model
demo followed by an installed, network-denied sub-30-second proof where two tenant
sessions do not leak, a real worker process is killed and restarted, the run reattaches
to ordered events, and a retained artifact remains readable without duplicating an
operation. A separate under-five-minute path uses a real provider. CLI, TUI, AgentOS,
remote, scheduled, and delegated use are secondary clients of that exact contract.

### 1. Architecture review

The public product remains small. `AgentHarness` owns validated reusable intent;
`HarnessRun` owns one execution; internal services own persistence and orchestration.
Agno remains the model/tool/learning engine, while agnoclaw owns the guarantees clients
observe across Agno versions.

```text
SDK / CLI / TUI / AgentOS / Remote / Scheduler
                    |
                    v
             AgentHarness facade
                    |
         validate + resolve trusted scope
                    |
                    v
            isolated RunRuntime  <---- CapabilityPlane
             |       |   |                |
             |       |   +------> Agno Agent + LearningMachine
             |       +----------> ContextManager / ArtifactStore
             +------------------> Policy / Approval / OperationGateway
                    |
                    v
      RuntimeStore (ledger + outbox + internal projections)
                    + ArtifactStore
                    |
                    v
       OpenTelemetry + evaluation evidence + audit export
```

Identity is one hierarchy, resolved only from trusted host input:

```text
tenant_id -> user_id -> session_id -> run_id -> attempt_id
                                      |             |
                                      |             +-> effect_id / idempotency_key
                                      +-> child run_id / artifact_id / event sequence
```

`session_id` remains the canonical conversational continuity and serialization key.
Documentation may explain the session as a conversational thread, but no peer
continuity identifier is added. A run is one
logical requested execution within a session; an attempt is one leased worker execution
of that run. Recovery/retry creates a new `attempt_id`, never a new `run_id`. A fork is a
new run with explicit checkpoint lineage. Every runtime-store key includes the required
tenant scope plus its canonical session/run/attempt/effect identity.

Lifecycle state machine:

```text
created -> queued -> running <--------------------+
                       |  |  \                    |
                       |  |   -> waiting_for_input|
                       |  +----> waiting_for_approval
                       |  +----> waiting_for_reconciliation
                       |  +----> paused -----------+
                       |  +----> cancelling -> cancelled
                       +-------> completed
                       +-------> failed
                       +-------> failed_with_unknown_effects
queued/waiting/paused --retention policy---------> expired
```

`waiting_for_reconciliation` may transition to `running`, `completed`, `cancelled`,
`failed`, or `failed_with_unknown_effects`, selected by the durable pending command,
effect outcome, and coordinator compare-and-swap. Operator settlement changes the
effect record; the coordinator alone derives any run transition. If reconciliation
arrives after a terminal `failed_with_unknown_effects`, it appends an effect event and
updates only the effect projection.

Only the run coordinator writes lifecycle transitions. Workers propose events and
effect settlements using compare-and-swap on `(run_id, expected_version)`. Terminal
states are immutable. Recovery leases execution; it never infers success from a missing
worker.

Architectural invariants:

1. No mutable Agno Agent, Function schema, prompt, identity, or learning scope is shared
   between overlapping runs.
2. A state/event/effect acknowledged to a client is durable in durable profiles.
3. One logical effect has one settlement record, even when delivery is at least once.
4. Context compaction never deletes the source trajectory or artifact by implication.
5. Learning candidates are data, not trusted behavior, until evaluation and promotion.
6. Every execution source enters the same run factory and policy boundaries.
7. Ephemeral/quick mode changes adapters and retention, never semantics.

### 2. Error and rescue map

| Boundary | Typed failure | Rescue and caller contract |
|---|---|---|
| Configuration/version | `ConfigurationError`, `UnsupportedCapabilityError` | Fail before model call; name required dependency/profile alternative. |
| Run admission | `RunConflictError`, `QuotaExceededError` | Reject or queue deterministically; no run-side mutation. |
| Model/provider | `ProviderError` with retry class | Retry only before irreversible effect or at a checkpoint; preserve attempt history. |
| Tool/effect | `EffectUnknownError`, `EffectFailedError` | Reconcile by idempotency key; wait for operator when settlement is unknowable. |
| Approval/input | `ApprovalExpiredError`, `InputExpiredError` | Durable wait, notify, expire by policy; never auto-approve. |
| Store/migration | `StoreUnavailableError`, `MigrationRequiredError` | Stop admission or use explicitly allowed degraded profile; never silently lose durability. |
| Context | `ContextOverflowError`, `CompactionQualityError` | Artifact spill, reactive compaction, bounded retry, then explicit failure with recovery data. |
| Learning | `LearningScopeError`, `CandidateRejectedError` | Quarantine/reject; base run may continue if policy marks learning noncritical. |
| Capability/MCP | `CapabilityUnavailableError`, `UntrustedCapabilityError` | Isolate server/capability, invalidate cache, offer governed fallback. |
| Child/job | `ChildRunFailedError`, `LeaseLostError` | Apply declared join/partial-failure policy; stale worker cannot commit new state. |
| Cancellation | `CancellationPendingError` | Expose in-flight effects and settlement progress; terminal only when policy resolves them. |

Error payloads include stable code, safe message, run/attempt/effect IDs, retryability,
recovery action, causal chain reference, and redacted diagnostics. Raw provider/tool
payloads stay in access-controlled artifacts, not exception strings.

### 3. Security and threat model

| Threat | Trust boundary | Required control |
|---|---|---|
| Cross-tenant data/tool leakage | Host identity -> run/store/cache | Trusted identity binding, scoped keys/queries, negative tests, no model override. |
| Prompt or tool-result injection | Untrusted content -> capability/policy | Content labeling, policy after model decision and before effect, allowlists, output handling. |
| Malicious skill/MCP server | Supply chain/network -> runtime | Pin/provenance, manifest/schema validation, sandbox, auth scopes, timeouts, quarantine. |
| Secret exfiltration | Environment/files/network -> model/tool | Secret broker/handles, redaction, egress policy, least privilege, audit. |
| Approval replay/confused deputy | Human decision -> effect | Bind approver, run, exact arguments, expiry, nonce, policy version, one settlement. |
| Learning poisoning | Trajectory/content -> future behavior | Candidate quarantine, provenance, held-out/adversarial eval, scoped promotion, rollback. |
| Replay privilege escalation | Persisted run -> new caller | Reauthorize every artifact/capability/effect under current policy and original ownership. |
| Resource exhaustion | Model -> tools/children/context | Token/time/cost/fan-out/storage quotas and circuit breakers. |
| Event/log leakage | Runtime -> telemetry clients | Content off by default, field classification, redaction before persistence/export. |
| Store tampering/corruption | Storage -> recovery | Version/checksum, transactionality, backup/restore, corruption classification. |

Security defaults are a migration with one mechanically distinguishable rule:
unprofiled `AgentHarness(...)` construction remains the warned legacy posture throughout
`0.12.x`; every explicit profile uses its documented posture, all new examples choose
the local-safe preset (or a stricter deployment policy) with `quick`/`durable`/`service`,
and diagnostics name both runtime profile and posture. A later default flip requires
the normal two-minor deprecation and may not infer whether an identical constructor call
is “new” or “old.”

### 4. Data flow and interaction edge cases

Normal durable run:

```text
start -> validate scope/policy -> persist created -> lease -> materialize isolated Agent
      -> persist running -> model/tool events -> effect intent -> approval? -> dispatch
      -> effect settlement -> checkpoint/context/learning candidates -> terminal commit
      -> reconnectable events/result
```

Shadow paths that must have first-class tests:

- caller disconnects before `start()` response: idempotency key returns the same run;
- worker dies after effect commit but before settlement write: reconciliation blocks
  retry until the external system or operator determines outcome;
- store succeeds but event notification fails: cursor polling recovers the durable row;
- event notification arrives twice/out of order: `(run_id, sequence)` deduplicates and
  orders consumption;
- cancellation races with approval, tool completion, child completion, or terminal
  commit: compare-and-swap chooses one legal transition and records the loser;
- compaction races with a new tool result: segment/version boundary prevents omission;
- learning deletion races with recall/promotion: tombstone/version blocks future use and
  audit shows any in-flight read;
- MCP server changes schemas mid-run: capability snapshot is pinned to the run; new runs
  see the new version after validation;
- parent is cancelled while a child has an external effect: cancellation propagates,
  then parent waits for declared child settlement policy;
- scheduler lease expires while the old worker returns: fencing token rejects stale
  commits;
- migration is interrupted: expand/migrate steps resume idempotently; contraction does
  not begin until old-reader counts reach zero.

`src/agnoclaw/agent.py` is already over 5,000 lines and mixes construction, execution,

### CEO spec-review resolution, round 1

The independent spec pass returned REVISE. All P0 contract findings are resolved here
and in R1-R12; the following details are normative for engineering review.

#### Transaction, deletion, and cursor contract

- SQLite uses one ACID runtime ledger for state transitions, event envelopes, effect
  intents/settlements, checkpoints metadata, job/lease changes, and an outbox. Other
  adapters must offer equivalent compare-and-swap and transactional-outbox semantics or
  fail certification.
- Projections are disposable and rebuildable from the ledger. Notification is
  at-least-once after commit. Clients deduplicate by `(run_id, sequence)`; no API claims
  exactly-once delivery.
- Artifact bytes are content-addressed and staged before ledger commit. The commit adds
  the authorized reference; failed/unreferenced staging is garbage-collected. A missing
  committed artifact is a typed corruption failure, never an empty result.
- Sensitive bodies live behind revocable encrypted content/artifact keys; append-only
  envelopes retain non-sensitive metadata and deletion tombstones. Deletion versions
  propagate to summaries, checkpoints, learning stores, indexes, caches, and exports.
  Backups have a documented maximum expiry and restore reapplies tombstones before use.
- Every profile declares event/artifact/checkpoint retention and a pruning watermark.
  A cursor below the watermark raises `CursorExpiredError` and returns the latest
  authorized projection/checkpoint reference when available; it never silently skips.

#### Lifecycle control safe points

| Operation | Acceptance and persistence | Effect on active work |
|---|---|---|
| `cancel()` | Durable command, authorized, idempotent | Stops new model/tool/child dispatch; settles or reconciles in-flight effects. |
| `command(Pause)` | Becomes `paused` only at a certified checkpoint | Active model stream may finish/abort by provider contract; external effect is never frozen mid-commit. |
| `command(Resume/Respond)` | Requires paused/waiting state, authorization, and valid lease | Creates a new attempt from the last certified checkpoint or resolves one typed wait. |
| `command(Steer)` | Durable ordered input for the next model boundary | Never mutates an already-issued model request or tool arguments. |
| `HarnessSession.start()` follow-up | Creates a new run/turn in the same session | Never extends or rewrites the immutable terminal run. |
| `get_run()` snapshot plus `events()` | Read-only, authorized projection | Executes no model, tool, learning write, or external effect. |
| `command(Fork)` | Requires authorized certified checkpoint; creates new `run_id` and lineage | New run receives a capability/policy snapshot and new effect keys. |

#### Capability trust and MCP conformance

| Class | Execution | Claim |
|---|---|---|
| Trusted in-process Python | Host process | Policy/audit/identity controls; no isolation claim against malicious code. |
| Sandboxed local | Restricted process/container backend | Filesystem/network/resource boundary certified per backend. |
| Remote MCP | Authenticated transport to untrusted server | Schema/content treated as untrusted; timeouts, scopes, quarantine, and egress policy. |
| Unsupported/unclassified | Any | Rejected by `durable` and `service` and by the local-safe preset; compatibility constructor only. |

The certified MCP client target is specification `2026-07-28` with Python SDK `2.0.x`
(official `v2.0.0`, released 2026-07-28) after T2 compatibility proof. Required for the
tool slice: stdio and Streamable HTTP, automatic current/fallback negotiation, bounded
pagination, structured content, schema-digest drift rejection, content-minimized
failures, conservative effects, and async run ownership. Selected resources, prompts,
subscriptions, Apps, Tasks, MRTR, and OAuth/enterprise identity remain capability-gated

are compatibility-only if a product integration needs them. A run pins selected schema

#### Evaluation and performance governance

- Benchmark manifests pin dataset, invariant schema, model/provider, scorer/prompt
  versions, seed, repetitions, hardware class, baseline commit, and approver. Score
  changes require an explanation and independent review; no silent golden refresh.
- Isolation, authorization, secret leakage, duplicate canonical settlements, and safety
  critical behaviors are zero-tolerance gates.
- Learning promotion requires the 95% confidence/credible lower bound for target utility
  improvement to exceed zero, overall task non-inferiority no worse than 1%, and no
  safety/privacy regression. Small datasets that cannot establish this remain shadow.
- Automatic compaction requires 100% deterministic retention of declared invariants,
  no more than 2% task-success non-inferiority on the long-run corpus, at least 30%
  median input-token reduction after trigger, and zero safety-constraint loss.
- Stage 0 captures raw-Agno and 0.11 baselines with a deterministic local provider.
  Initial quick-mode budgets are p50 <= max(5%, 10 ms), p95 <= max(10%, 25 ms), and
  p99 <= max(15%, 50 ms) over raw Agno for kernel-only overhead; provider latency is
  reported separately.
- Capability fixtures at 10/50/200/1,000 entries target <=1,500 initial schema tokens,
  >=95% recall@10, <=1% false activation, and <=100 ms p95 local discovery at 1,000.
  Engineering may tighten, but not weaken, these values after baseline without a logged
  CEO/release decision.

#### Remote protocol and compatibility operations

- A versioned wire envelope carries protocol version, run/session/attempt IDs, sequence,
  state/event/error schema version, idempotent start key, cursor, approval/input message,
  capability snapshot, and redacted diagnostics. SDK, AgentOS, and remote clients
  negotiate compatible major/minor behavior before run admission.
- Learning migration performs discovery, backup, scope-map dry run, collision report,
  freeze or dual-read window, idempotent copy, count/hash verification, cutover marker,
  deletion/tombstone propagation, and explicit rollback boundary. It never dual-writes
  to ambiguous legacy scope.
- Weekly CI tests the next Agno and MCP SDK releases. The compatibility DRI responds to

#### Canonical glossary

- **Session:** conversational continuity and serialization boundary (`session_id`).
- **Run:** one logical requested execution (`run_id`).
- **Attempt:** one leased worker execution/recovery try (`attempt_id`).
- **Effect:** an externally visible operation with correlation and settlement identity.
- **Event:** an immutable ordered observation in the runtime ledger.
- **Checkpoint:** certified state from which an attempt may resume or a new run may fork.
- **Reconstruct:** read-only projection from ledger/checkpoint data.
- **Fork:** new effect-capable run with lineage from a certified checkpoint.

Documentation lint rejects a second continuity identifier, peer run-handle/spec types,
summary-only compaction claims, and ambiguous effectful “replay” in current-contract docs.

### Resolved runtime architecture

```text
trusted host/adapter input
          |
          v
AdmissionResolver ---- conflict ----> typed redacted rejection
          |
          v
immutable AdmissionEnvelope + compiled _HarnessSpec
          |
          v
RunCoordinator --command--> pure StateReducer
          |                       |
          |                       v
          +--------------> RuntimeTransaction/UoW
                                  |
                 +----------------+----------------+
                 |                |                |
          state + event       mutation row      outbox row
          sequence CAS       effect/job/etc.   same commit
                 |
                 v
      lease + per-run/session materializers
                 |
          isolated Agno Agent
                 |
     model/capability request
                 v
           OperationGateway
      intent -> policy -> approval?
                 |
              dispatch
                 |
       settlement/reconciliation
                 |
      context + LearningGateway
                 |
         terminal transaction
```

The reducer is pure and storage-agnostic. The unit-of-work is the only commit authority.
Workers propose commands with expected versions and fencing tokens; the coordinator
accepts or rejects them. Projections, notifications, telemetry exporters, Agno session
history, and Agno learning stores are downstream and rebuildable or explicitly
reconciled. No callback is allowed to create a second truth.

The local and remote handles share a structural versioned protocol, not necessarily one
concrete Python class. `get_run()` reattaches by authorized `run_id`. `events()` has
finite default semantics and explicit long-follow semantics. A post-terminal effect
reconciliation appends an effect event without mutating the run terminal state.

`src/agnoclaw/agent.py` is more than 6,600 lines and currently combines facade,
construction, prompt assembly, tools, policies, permissions, events, storage, context,

Protocols use typed immutable domain values and async-first internals. Sync behavior is

`harness._agent.db` and use coordinator/store interfaces; durable approvals become
waiting commands, not rejection records bolted around a live Agent call.

### Transaction and failure rules

- Acknowledgement occurs only after the ledger commit. Notification is at-least-once.
- SQLite uses WAL, busy timeout, explicit transaction mode, database clock, bounded
  writer queues/batches, and documents that unsupported network filesystems are not a
  certified service store.
- Artifact bytes stage by hash before the authorized ledger reference. Missing committed
  bytes are corruption, not an empty result.
- Stream deltas batch separately from logical events; state/effect/approval/terminal
  writes never become best-effort.
- Agno session/learning projection writes use stable source IDs. A commit on one side
  and lost response on the other is reconciled, not guessed.
- Model-selected tools, deterministic skill commands, custom tools, MCP, elevated
  commands, children, and jobs have one governed dispatch path.
- Every acquired capability and isolated harness used by jobs/children closes on normal,
  failure, cancellation, and worker-loss paths.
- Typed errors are classified and redacted before they enter the ledger or exception;
  export-time redaction alone is too late.
