# v0.12.0 implementation progress

Status: release-candidate verification

## Product-owner scope reset — 2026-08-20

The 0.12 release gate now optimizes for the product's actual maturity: feature
completeness on the supported paths, excellent developer ergonomics, a small and
coherent public interface, useful documentation and support diagnostics, and
reasonable safety for current users. It does not require production-scale operating
proof intended for a mature multi-tenant service before the project has that user base.

The following remain release requirements:

- the documented quick, durable, and service interfaces behave consistently and fail
  clearly when a requested guarantee or optional dependency is unavailable;
- the common single-agent, registered-tool, skill, MCP, context-continuity, learning,
  child-run, scheduling, inspection, and migration journeys are tested and documented;
- clean wheel/sdist installs, executable examples, stable errors, migration help, and
  operator-facing inspection provide a world-class first-use and support experience;
- no known critical/high-impact defect may expose credentials, cross ownership
  boundaries, bypass explicit-profile policy, dispatch an ambiguous external effect, or
  publish an unverifiable artifact; and
- unsupported advanced recovery or deployment shapes are named and either rejected
  before effects or documented without implying certification.

The following are valuable post-0.12 hardening, not release blockers: multi-AZ quorum,
STONITH/watchdog integration, hostile network-partition and certificate-rotation
matrices, production-volume RPO/RTO proof, hours-long multi-worker soak, every cloud
provider/vector store combination, long-duration learning-drift studies, advanced
Collector chaos, and transparent reconstruction of arbitrary nested/parallel/raw/
streaming/parser/output-model stacks. These remain tracked; the scope change does not
permit false claims about them.

## Known current limitations

- Non-streaming model/registered-capability runs using run-owned managers and immutable
  seeds can overlap through distinct Agents. Supported host-local built-ins also get
  distinct Agents/tools and exact release; every constructed first-party call is now
  ledger-governed, but effects remain safe by single-flight rejection. Optional/custom
  backends, contexts, packs/plugins, caller-supplied MCP, other mutable resources, and streams
  do the same; use a harness per concurrent worker until their materializers and overlap
  routing are certified.
- `start/get_run` now persist and settle the outer model operation, can recover its
  known-success result artifact, and can continue the exact settled pre-model request
  safe point. On the certified Agno 2.9 path, separate provider operations/artifacts
  plus the native `tool-batch` checkpoint resume one governed capability sequence;
  before that checkpoint, an approval wait reconstructs from exact provider/approval/
  frozen-authority evidence. Ambiguity parks in a typed wait and bounded exact-owner
  observers can evidence-settle/continue the outer operation. They cannot reconstruct
  nested/parallel/raw/streaming/parser/output-model stacks, supply provider-specific
  proof automatically, or resume unsupported extension settlements. Explicit-profile
  `run/arun` now enters `start()` plus `wait()`; only the named legacy profile stays on
  the direct path. Synchronous calls reuse one harness-owned event loop and bounded raw
  presentations detach independently from logical runs. The first-party non-interactive
  CLI, heartbeat, and local
  scheduler select lifecycle start/wait for explicit profiles. Async chat/TUI
  uses the same lifecycle model operation with a bounded live display and terminal
  reconciliation; extracted text is artifact-backed and cursor-replayable, while raw
  provider event objects and live tool UI state remain process-local. Explicit profiles
  reject raw subagent/Team/specialized-skill ingress before effects;
  named legacy retains those paths without lifecycle parity. Host code, model tools,
  and remote clients use the capability-only `DeclaredChildTemplate` path instead.
- lifecycle-emitted normalized events are authoritative, bounded `trajectory.*`
  projections, and `RuntimeOutboxWorker` now provides the durable generic delivery
  boundary. The immediate `EventSink` remains a best-effort compatibility notification.
  Named-legacy `run/arun`, native provider streams, an explicit schema registry, independent
  audit anchoring/operator UI, tenant fairness, and first-party OTEL/client destination
  adapters remain open.

  request. Exact decision retry and one Agno 2.9 process-death reconstruction envelope

  ingress or nested/parallel/streaming/parser/output-model sequence.
